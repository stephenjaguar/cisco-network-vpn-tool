Cisco Network Automation & IPSec VPN Planning Tool

A practical interview project showing automation design, mock-first validation, Netmiko extensibility, compliance reporting, and FortiGate-to-Palo Alto VPN planning.

The Thinking Behind the Design

Reliability first The demo works without licensed Cisco images, hypervisors, or physical devices by using a deterministic mock driver.
Real automation shape The app still follows the real workflow: connect, configure, save, back up, validate, and report.
Easy upgrade path The same interface supports a Netmiko driver for a real Cisco IOS switch when lab hardware is available.

Why Mock the Cisco Switch?

The task constraints avoid VMware and VirtualBox. GNS3 and EVE-NG commonly depend on VM-based appliances, and Cisco IOL images require licensing. A mock driver removes those blockers while still proving the application logic.

The mock is not a fake test shortcut. It emulates the command outputs the validator depends on, including show vlan brief, show run | i hostname, and a running config backup.

How the Application Works

  1. The Flask UI collects device IP, username, password, driver mode, and hostname.
  2. The app creates either MockSwitchDriver or NetmikoSwitchDriver.
  3. The driver applies hostname and VLAN intent.
  4. The driver saves configuration with write memory.
  5. The driver writes a local backup file under backups/.
  6. The validator checks command output against intended state.
  7. The UI renders a compliance report with pass/fail checks.

Automation Flow

Flask form
  -> create_driver("mock" or "netmiko")
  -> connect()
  -> push_hostname("AUTOMATED_SWITCH")
  -> push_vlan_config({10, 20, 50})
  -> save_config()
  -> backup_config()
  -> validate_switch_state()
  -> render compliance report

How to Connect to a Real Physical Cisco Switch

Use this only on lab equipment or a switch where changes are approved. The app will configure hostname and VLANs, save the config, and back up the running config.

1. Cable and IP Connectivity

  • Connect your Mac to the switch management network.
  • Assign the switch a reachable management IP.
  • Confirm your Mac can reach the switch with ping.

2. Prepare SSH on Cisco IOS

enable
configure terminal
hostname LAB-SW1
ip domain-name lab.local
username admin privilege 15 secret StrongPassword123
crypto key generate rsa modulus 2048
ip ssh version 2
line vty 0 4
 login local
 transport input ssh
exit
interface vlan 1
 ip address 192.168.1.10 255.255.255.0
 no shutdown
exit
ip default-gateway 192.168.1.1
end
write memory

3. Verify SSH from macOS

ping 192.168.1.10
ssh admin@192.168.1.10

Do not run real-device mode on production equipment without approval and a rollback plan.

Interview Talking Points

  • The mock driver keeps the demo portable and deterministic.
  • The driver abstraction separates UI and business logic from transport details.
  • Validation is based on observed device output, not only successful command submission.
  • Backups are generated automatically before the operator reviews compliance.
  • The VPN plan shows awareness of multi-vendor API differences and Proxy-ID selector mismatch risk.
